# 技术决策记录

下列条目记录当前源码体现的做法。理由结合历史设计与实现归纳，新增或替代方案在确认后单独登记。历史背景见 [早期设计](superpowers/specs/2026-11-14-ai-career-platform-design.md) 和 [开发交接](../HANDOVER.md)。

| 决策 | 原因 | 已知限制与依据 |
| --- | --- | --- |
| 单体 FastAPI 配合 Jinja2、Bootstrap 和原生 JavaScript | 课程环境可用一套 Python 服务交付页面、接口和文件，减少前端构建和部署环节 | 页面和 API 共用应用进程。浏览器需要为录音和状态轮询提供相应能力。依据 [应用入口](../app/main.py) |
| SQLite 与 SQLAlchemy，旧库停机补列 | 单实例下便于启动、备份和维护，外键约束结合 WAL 与忙等待处理本地并发访问。P3／P4 增量迁移保留旧数据 | `create_all` 只能建缺失表，迁移脚本面向本地 SQLite 文件。增加迁移工具的时机待确认。依据 [数据库配置](../app/db.py)及 [P3](../scripts/migrate_p3.py)、[P4](../scripts/migrate_p4.py)脚本 |
| 签名会话 Cookie、bcrypt 和后端权限守卫 | 以同源会话支持三角色页面，在服务端检查角色和资源归属 | 当前 `SameSite=Lax`，Cookie 未强制 HTTPS，配置有开发默认密钥。公网安全加固见 [路线图](ROADMAP.md)。依据 [认证](../app/auth.py)及[会话配置](../app/main.py) |
| 确定性匹配与来源摘选简历 | 相同的技能输入可得到可复核的规则分。模型负责解释或选择现有经历条目，服务端校验编号并回填，降低凭空生成经历的风险 | 匹配依赖学生自评及岗位技能质量。简历自由文本仍需本人核对，分页受字体和客户端影响。依据 [匹配规则](../app/services/matching.py)、[简历摘选](../app/services/resume.py) |
| 逐题语音及供应商接口 | 课程方案采用逐题录音或上传，阶段化状态支持重试。文本与语音各用独立客户端，可配置服务地址 | 语音替代视频的课程验收待确认。录音需安全上下文，云端供应商效果、费用和延迟待测。依据 [P3 验证](p3-verification.md)、[面试路由](../app/routers/interview.py) |
| 持久任务状态与进程内单消费者 | 任务状态写入 SQLite，刷新后仍可查询，重启可恢复处理中任务。部署仅需一个应用进程，无额外队列服务 | 锁无法协调多个进程，恢复也可能重复外部计费。需单应用实例，跨进程领取方案待确认。依据 [面试消费者](../app/services/interview_worker.py)、[导出消费者](../app/services/resume_export_worker.py) |
| 教师导出使用快照、显式授权及版本失效 | 快照使重试使用一致内容。联系方式默认私密，修改或撤回会使包含旧联系方式的任务失效。导出复用简历生成服务，结果与学生私人简历分开保存 | 任务有效期 24 小时，已传出的文件不能撤回，自由文本不自动脱敏。依据 [联系方式更新](../app/routers/profile.py)、[导出快照](../app/services/resume_exports.py) |

## P5 本机演示技术决策

2026-11-22 收尾确认，以下决策已在 `2205dba` 实现。

| 决策 | 理由 | 影响与验证入口 |
| --- | --- | --- |
| 通过兼容 API 接入本机文本和语音服务 | 在 Windows 本机提供免费演示，复用现有客户端和任务流程 | 文本使用 Ollama，语音使用 faster-whisper 和 Windows 音色。运行依赖本机模型权重和工具。见 [安装说明](../README.md#windows-本机免费模型) 和 [语音边界测试](../tests/test_local_speech.py) |
| 严格 JSON Schema 按配置启用 | 本机小模型容易遗漏字段。以已有校验模型约束输出，业务校验继续保留 | 结构化模式用于简历和面试，普通 JSON 模式仍为默认。缺少有效锚定的追问使用已核实原文和通用问题。见 [模型请求测试](../tests/test_job_skills.py) 和 [面试回归](../tests/test_interview_ai.py) |
| 单一启动入口管理本机依赖 | 防止继承变量改变请求去向，并减少手动启动和停机顺序错误 | 启动时核对有效配置和服务身份，运行时监测依赖。故障恢复仅作用于自有进程且次数有限。网页先排空，超时后强制关闭并由既有任务恢复逻辑接手。见 [启动器回归](../tests/test_local_ai_launcher.py) |

新增决策时记录日期、状态、问题背景、选定方案、考虑过的方案、具体影响和可验证的源码或测试入口。
