# AI 赋能职业发展与面试指导平台 — 设计文档

- 日期：2026-11-14
- 状态：已批准（2026-11-14）

- 课程：人工智能实践
- 交付周期：2 周以内

- 代码仓库：https://github.com/yu1gg/task1.git

## 1. 背景与目标

面向本专业师生，做一个「AI 职业发展 + 面试指导」平台，解决指导书列出的五个痛点：新生不了解就业去向、教师难以精准推荐学生、学生不知道实习机会与需培养的技能、简历写作困难、缺少简历评价与面试指导。

产品目标：

1. 打通「企业岗位 → AI 技能拆解 → 学生能力自评 → AI 简历 → AI 视频面试 → 人岗匹配推荐」的完整闭环。
2. 让低年级学生能看到目标岗位与能力差距，尽早开始积累。
3. 让教师能按企业岗位快速筛选学生、批量生成针对性简历。
4. 真实部署到外网，积累 10 位以上真人用户和可核验的使用记录。
5. 完成精益画布、技术总结报告、测试报告、宣传视频和答辩 PPT。

### 3.2 明确不做

- 附录扩展功能：AI 爬虫抓岗位、标准化题库测评、完整 AI 用户画像、行业标杆人物库、教师学情看板、学校课程改革报告。
- 实时音视频通话、WebRTC、数字人 API、第三方虚拟人服务。
- 微信小程序、原生 APP。
- 邮箱验证、找回密码、第三方登录（微信/QQ）、短信验证。
- 多套简历主题、复杂排版设计器、在线支付、企业独立账号体系（企业批量下载由教师账号代为完成）。
- 人脸表情分析、眼神分析等生物特征分析。

### 3.3 关键妥协与说明

1. **异步视频面试**：公网 HTTP + IP 下，浏览器禁止 `getUserMedia`（摄像头/麦克风），因此线上采用「AI 语音提问 + 学生录制/上传视频回答 + AI 转写追问」的异步视频问答。它符合「不能是纯文字面试」的底线，但不是实时视频通话。报告和 PPT 中必须如实说明。
2. **答辩增强模式**：同一套面试页面在 `localhost` 或 HTTPS 下会自动启用浏览器实时录像（`MediaRecorder`），答辩时可在自己电脑上演示实时摄像头画面。线上版本自动降级为文件上传。这样既保证真实上线，也保留更好的答辩演示效果。
3. **异步视频的合规风险**：若指导老师明确要求实时视频/电话面试，备选方案是答辩前用免费 HTTPS 临时隧道（无需购买域名）开启实时录像模式，或提前与老师确认异步视频是否接受。该风险在项目开始时必须确认。
4. **HTTP 明文传输**：公网 HTTP 下账号密码和数据以明文传输。只使用演示性质的数据，不收集敏感个人信息；密码哈希存储；报告中说明该限制和未来 HTTPS 方案。

## 4. 角色与权限

| 角色 | 注册方式 | 权限 |
|---|---|---|
| 学生 | 自由注册 | 编辑个人资料与技能；浏览岗位；查看差距与匹配；生成/编辑/下载自己的简历；参加面试；查看自己的面试报告；录入岗位 |
| 校友 | 自由注册 | 录入岗位；浏览岗位；可查看岗位技能要求；不参与匹配排名 |
| 教师 | 邀请码注册 | 创建/编辑岗位；确认 AI 拆解技能；查看学生资料、匹配排名与面试报告；批量生成/下载简历；导出使用记录；不创建学生简历或参加面试 |

权限规则：

- 用户只能访问自己的简历、面试记录、上传视频；教师只能访问报告/转写和批量生成的简历，默认不直接访问学生原始视频。
- 教师邀请码放在环境变量 `TEACHER_INVITE_CODE`，不写入代码仓库。
- 所有写操作先校验登录态和角色。

## 5. 用户主流程

1. 注册/登录，选择角色（教师需邀请码）。
2. 教师、学生或校友录入企业和岗位信息。
3. AI 拆解岗位技能，教师检查并修正重要性/等级。
4. 学生完善教育、技能自评、项目、实习、奖项，选择目标岗位。
5. 学生点击「生成简历」：AI 按目标岗位生成结构化内容，学生在表单中编辑，预览 A4，下载 DOCX 或打印 PDF。
6. 学生进入「视频面试」：选择岗位和轮次 → AI 语音提问 → 学生用手机录制/上传视频回答 → AI 转写、评分并追问 → 5–8 轮后生成面试报告。
7. 教师在岗位页查看匹配排名与差距，勾选学生，批量生成针对该岗位的简历并打包 ZIP 下载。
8. 教师在后台导出使用记录 CSV，作为真实用户证据的一部分。

## 6. 功能需求

### 6.1 注册与登录

- 输入：用户名（唯一）、密码、真实姓名、角色、专业、年级（学生）。
- 行为：注册时校验用户名唯一；密码使用 bcrypt 哈希；教师角色校验邀请码。
- 输出：登录后写入签名 Session Cookie（HttpOnly、SameSite=Lax）；跳转角色首页。
- 验收：错误密码/重复用户名有明确提示；未登录访问受保护页面跳转登录；退出后会话失效。

### 6.2 企业与岗位录入

- 输入：企业名称、行业、规模、地点；岗位名称、JD、要求、地点、薪资范围（可选）、招聘人数、截止日期、期望到岗时间（可选）。
- 行为：企业可按名称复用；岗位保存后状态为 `open`；录入人可编辑自己的岗位。
- 输出：岗位列表（按截止日期/创建时间排序）、岗位详情。
- 验收：学生/校友/教师均可录入；必填校验；岗位详情可正常展示。

### 6.3 AI 岗位技能分析

- 输入：岗位 JD、岗位要求、企业信息。
- 行为：调用 LLM，输出结构化 JSON：岗位摘要、职责要点、技能列表（名称、类别、必须/加分、要求等级 1–5）。
- 输出：写入 `job_skills`；岗位详情页展示技能清单；教师可编辑/删除/新增技能。
- 失败处理：LLM 超时或 JSON 解析失败时重试 2 次；仍失败则提示教师手动录入技能。
- 验收：拆解结果可编辑；技能能用于匹配和简历定制。

### 6.4 学生资料与技能自评

- 输入：姓名、联系方式、教育经历、技能自评（1–5）、项目经历、实习经历、奖项、个人简介、可实习/可到岗时间。
- 行为：技能清单来自岗位技能库 + 自定义技能；每项技能可填项目证据。
- 输出：保存到 `student_profiles`；首页显示资料完成度。
- 验收：可以保存和再次编辑；未填必填项时提示补齐。

### 6.5 AI 简历生成、编辑与导出

- 输入：学生资料、目标岗位、岗位技能。
- 行为：LLM 生成结构化简历 JSON；禁止编造经历；按岗位裁剪内容；目标 1 页 A4。
- 编辑：姓名/联系方式、个人简介、教育、技能、项目、实习、奖项均可表单编辑。
- 预览：HTML A4 比例预览，单栏、紧凑、整洁。
- 导出：DOCX（python-docx，单栏模板）；浏览器打印为 PDF；最多 1.5 页，目标 1 页。
- 约束：总正文控制在约 900–1200 中文字符；个人简介 ≤120 字；每个项目 2–3 条，每条 ≤60 字；技能 ≤12 项。
- 失败处理：LLM 解析失败重试；导出失败提示重试；页数超限提示精简内容。
- 验收：生成内容只包含学生真实信息；导出文件可在 Word/WPS 正常打开；打印预览不超过 1.5 页。

### 6.6 异步视频模拟面试

- 入口：选择目标岗位（必需）和轮次（一面=技术面 / 二面=HR 综合面）；可关联一份简历。
- 提问：LLM 根据岗位技能、简历、上一轮回答生成问题；AI 头像 + 口型动画 + TTS 语音播报，同时显示文字。
- 回答：学生录制/上传 90 秒以内的视频（≤100MB）；手机端通过 `<input type="file" accept="video/*" capture="user">` 调起相机；桌面端可上传文件。
- 处理：后端保存视频 → ffmpeg 抽取 16k 单声道 WAV → ASR 转写 → LLM 评分并生成下一问 → TTS 生成下一问音频。
- 追问：LLM 必须引用上一轮回答中的具体内容；一面（技术）围绕项目、技能深度、问题解决；二面（HR 综合）围绕动机、团队协作、职业规划、沟通表达；不涉及隐私/歧视性问题。
- 轮次：5–8 个问题，可在配置中调整。
- 报告：总分、专业能力、逻辑思维、沟通表达、岗位匹配度四项评分；优势、短板、每条回答摘要、3 条改进建议。
- 状态：上传后返回 `turn_id`，前端轮询处理状态；失败可重试或重新上传。
- 双模式：`window.isSecureContext` 为真（HTTPS/localhost）时启用浏览器实时录像；否则使用文件上传。
- 隐私：不做人脸分析；原始视频仅学生本人可访问；教师查看转写和报告。
- 验收：至少完成 5 问；追问与上一答相关；报告可查看；上传失败有明确提示。

### 6.7 人岗匹配与批量导出

- 输入：岗位技能（含必须/加分、要求等级）、岗位期望到岗时间、学生技能自评、项目证据、可到岗时间。
- 匹配算法：
  - 技能名归一化（小写、去空格、常用别名）。
  - 单项覆盖率 = min(学生等级 / 要求等级, 1)。
  - 权重：必须 = 3，加分 = 1。
  - 匹配分 = 100 × Σ(权重 × 覆盖率) / Σ(权重)。
  - 差距清单 = 覆盖率 < 1 的技能，按权重和差距降序。
- 时间适配：到岗时间不参与技能分计算，但在排名页显示并支持筛选，避免推荐无法到岗的学生。
- LLM 解释：基于分数和差距生成 2–3 句匹配理由 + 3 条学习建议；规则分是主结果，LLM 不修改分数。
- 教师视图：按岗位查看学生排名、匹配分、差距摘要、可到岗时间；可按到岗时间筛选；可勾选学生。
- 批量导出：对每位选中学生生成针对该岗位的定制简历 DOCX，打包 ZIP 下载。
- 验收：排名与技能数据一致；ZIP 内文件命名规范（姓名_岗位.docx）；无技能数据时不崩溃并提示。

### 6.8 低年级引导

- 岗位详情页：显示该岗位要求技能、学生当前等级、差距、推荐学习方向。
- 学生首页：显示匹配度较高的岗位、待补齐技能数量、最近面试成绩。
- 验收：信息与匹配算法一致；页面在手机上可读。

### 6.9 使用记录与证据

- 记录事件：注册、登录、创建岗位、AI 拆解、保存资料、生成简历、下载简历、开始面试、提交回答、完成面试、批量导出。
- 字段：用户、事件类型、对象 ID、时间、IP、User-Agent、可选附加信息。
- 教师可导出 CSV。
- 验收：10 位真实用户的记录可追溯；CSV 包含姓名、事件、时间。

## 7. AI 设计

### 7.1 模型与供应商

| 能力 | 默认 | 备选 | 说明 |
|---|---|---|---|
| LLM | DeepSeek `deepseek-chat` | 通义千问、智谱 GLM | OpenAI 兼容接口；低温度用于结构化任务 |
| ASR | SiliconFlow `FunAudioLLM/SenseVoiceSmall` | 讯飞、阿里云智能语音 | 16k 单声道 WAV；短音频 |
| TTS | SiliconFlow CosyVoice | edge-tts | 生成 MP3/WAV；缓存问题音频 |

- 所有供应商通过 adapter 接口调用，密钥放 `.env`。
- 第 1 天做连通性验证；若模型名/接口有差异，按官方文档调整 adapter，不改变业务代码。
- 不在代码中硬编码密钥；`.env` 加入 `.gitignore`。

### 7.2 结构化输出

- 所有 LLM 输出必须为 JSON，使用 Pydantic 模型校验。
- 校验失败时带错误信息重试 2 次；仍失败则返回可读错误，不写入半成品数据。
- 主要 Schema：
  - `JobSkillExtraction`：岗位摘要、职责、技能列表。
  - `ResumeContent`：姓名、联系方式、目标岗位、简介、教育、技能、项目、实习、奖项。
  - `InterviewEvaluation`：四项评分、优势、短板、更优回答、下一问、是否结束。
  - `InterviewReport`：总分、四项评分、优势、短板、逐题摘要、改进建议。

### 7.3 Prompt 规则

- 简历：只使用学生提供的事实；不得编造公司、时间、奖项、数据；按目标岗位调整措辞和项目顺序；控制字数。
- 岗位拆解：区分必须技能和加分技能；要求等级按初级/中级/高级映射到 1–5。
- 面试：问题要具体、可回答、由浅入深；追问必须引用上一答；避免隐私、歧视、与岗位无关的问题。
- 匹配解释：引用具体差距技能，给出可执行的学习建议；不夸大匹配度。
- 成本：限制输入长度；面试只携带最近 3–4 轮对话和一份历史摘要；岗位拆解结果落库复用；记录 token 消耗便于报告。

### 7.4 失败与降级

- LLM 失败：重试；仍失败则提示稍后再试，保留用户已输入内容。
- ASR 失败：提示重新录制/上传，或允许仅上传音频重试。
- TTS 失败：显示问题文字，使用浏览器 `speechSynthesis` 兜底。
- 视频处理失败：保留原文件，记录错误，允许重新提交。

## 8. 技术架构

### 8.1 技术栈

- 后端：Python 3.10+、FastAPI、Jinja2、SQLAlchemy 2.0、SQLite（WAL）。
- 前端：Bootstrap 5 本地静态文件 + 少量原生 JS；响应式布局。
- 文件：python-docx 生成简历；ffmpeg 处理视频；ZIP 打包用标准库。
- 认证：签名 Cookie Session；bcrypt 密码哈希。
- 部署：Uvicorn + systemd；可选 Nginx（MVP 不强制）。

### 8.2 组件

```
浏览器（Jinja2 页面 + 原生 JS）
        │ HTTP
        ▼
FastAPI 应用
  ├─ 认证/权限
  ├─ 岗位与技能
  ├─ 学生资料
  ├─ 简历（LLM + DOCX）
  ├─ 面试（上传 + 后台处理 + 轮询）
  ├─ 匹配与批量导出
  └─ 使用记录
        │
        ├─ SQLite（业务数据）
        ├─ 本地文件（视频/音频/简历）
        └─ 外部 API（LLM/ASR/TTS）
```

### 8.3 耗时任务

- 视频回答上传后立即返回 `turn_id`，不阻塞请求。
- 后台线程池（最大并发 1）执行：校验 → ffmpeg 抽音轨 → ASR → LLM → TTS → 写库。
- 前端每 2 秒轮询 `/api/interview/turns/{turn_id}`；完成后展示转写、评分和下一问。
- 使用线程锁限制同时处理数量，避免 2C2G 服务器过载。
- 批量简历生成同样走后台任务 + 进度页；10 人以内可同步降级。

## 11. 非功能需求

- **移动端**：Bootstrap 响应式；面试页全屏布局；手机端可拍照/录像上传。
- **性能**：10 人同时使用不崩溃；页面首屏在校园网/手机流量下尽量 <3 秒；90 秒视频处理目标 <60 秒。
- **可靠性**：systemd 自动重启；SQLite 每日备份；健康检查；上传失败可重试。
- **安全**：密码哈希；会话过期；权限校验；上传类型/大小校验；私有文件不暴露静态目录；Jinja 自动转义防 XSS；SQLAlchemy 参数化防注入；写操作 SameSite=Lax。
- **隐私**：只收集必要信息；原始视频仅本人可访问；用户证据需征得同意；不伪造。
- **成本**：LLM/ASR/TTS 调用上限可控；缓存岗位拆解和面试问题音频；监控每日花费。

## 12. 部署方案

### 12.1 环境

- 阿里云 Linux（优先 Ubuntu 22.04，实施时确认）。
- 安装：Python 3.10+、python3-venv、ffmpeg、sqlite3、构建工具。
- 代码目录：`/opt/career-app`；虚拟环境 `.venv`；数据目录 `data/`。
- 环境变量：`DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY`、`SESSION_SECRET`、`TEACHER_INVITE_CODE`、`APP_BASE_URL`。

### 12.2 启动与网络

- systemd 服务运行：`uvicorn app.main:app --host 0.0.0.0 --port 8080 --workers 1`。
- 阿里云安全组放行 TCP 8080；不使用 80/443（无备案域名）。
- 访问地址：`http://<公网IP>:8080`。
- 若校园网限制非标准端口，准备备用端口（8000/8888）并提前测试。
- 健康检查：`/healthz` 返回应用和数据库状态。

### 12.3 备份与运维

- 每日 cron：SQLite `.backup` + 上传目录打包，保留 7 天。
- 日志：systemd journal + 应用日志。
- 部署后自测：注册、登录、建岗位、生成简历、上传视频、完成面试、匹配导出。
- 上线前用校园 Wi-Fi、手机流量各测一遍。

### 12.4 HTTPS 与实时录像说明

- 公网 HTTP 不能调用摄像头/麦克风；线上使用异步视频上传。
- `localhost` 或 HTTPS 下自动启用实时录像，供答辩演示。
- 若答辩必须线上实时，备选免费 HTTPS 隧道（不购买域名）；该方案需提前一天演练。

## 13. 测试策略与验收

### 13.1 测试类型

- 单元测试：匹配分数、技能归一化、简历 Schema 校验、密码哈希、权限判断。
- 集成测试：FastAPI TestClient + mock LLM/ASR/TTS，覆盖注册 → 岗位 → 技能 → 简历 → 面试 → 匹配。
- 手工端到端：完整主流程；手机端；异步视频上传；失败重试。
- 兼容性：Chrome/Edge、iOS Safari、Android Chrome；校园 Wi-Fi 与手机流量。
- 安全测试：未登录访问、越权访问他人简历/视频、非法文件上传、超长输入。
- 性能：10 个用户并发核心操作；90 秒视频处理时长。

### 13.2 验收标准

1. 新学生能注册、完善资料、查看岗位差距、生成并下载 ≤1.5 页简历。
2. 学生能完成至少 5 问视频面试，获得转写、四项评分和报告；追问与回答内容相关。
3. 教师能创建岗位、查看 AI 技能、按匹配度排序、批量下载定制简历 ZIP。
4. 公网 `IP:8080` 可访问，手机可完成核心流程。
5. 10 位以上真实用户有可追溯使用记录与证据。
6. 精益画布、技术总结报告、测试报告、宣传视频、PPT 全部完成。

## 14. 10 位真实用户与证据计划

- 招募：同班同学优先，可跨专业；每人真实姓名，征得公开展示同意。
- 最低使用标准：注册 + 完善资料 + 生成简历 + 完成 1 次视频面试。
- 教师账号演示：创建岗位、查看匹配、批量导出。
- 证据材料：
  - `usage_events` 导出 CSV（姓名、事件、时间、IP）。
  - 每位用户关键页面截图或录屏。
  - 问卷星/腾讯问卷反馈结果（5 题以内）。
  - 微信群/QQ 群沟通截图（征得同意）。
- 不足 10 人时继续招募或扩大范围；**绝不编造用户、记录或截图**。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 异步视频被判不符合“视频面试” | 可能丢分 | 项目开始即向老师确认；答辩用 localhost 实时录像演示；报告如实说明；备选免费 HTTPS 隧道 |
| LLM/ASR/TTS 接口不可用或限流 | 核心功能失败 | Adapter + 备选供应商 + 缓存 + D1 早验证 + 降级文案 |
| 2 周时间不足 | 交付不完整 | 砍功能顺序：头像动效打磨 → PDF 批量 → 首页岗位推荐 → HR 轮次；核心链路不砍 |
| 手机上传视频失败/过大 | 面试无法完成 | 90 秒/100MB 限制；服务端压缩；重试；允许音频兜底；录制指引 |
| 真实用户不足 10 人 | 不满足提交要求 | 提前招募；一对一指导；跨专业扩展；不造假 |
| 服务器/网络不稳定 | 答辩事故 | systemd 自启；健康检查；备份；多网络测试；备用端口 |
| HTTP 明文传输 | 隐私/安全问题 | 不收集敏感信息；演示性质；密码哈希；报告说明；未来 HTTPS |
| AI 编造简历内容 | 诚信问题 | Prompt 强约束 + 学生自行核对 + 编辑确认 |
| 简历页数超限 | 不符合要求 | 字数上限 + 预览核验 + 精简提示 |
| 批量生成耗时 | 教师等待 | 后台任务 + 进度页；10 人以内可接受 |
