# P2 简历实施与验收

日期：2026-11-14。范围：学生简历，P3–P5 不在本轮实现范围。

## 已确认的实现决策

- AI 只选择来源编号与排序，程序回填原资料，不改写经历、不补造 STAR 结果。
- 复用 `resumes.content_json`，联系方式只存在简历中，不改表。
- 每次生成新建记录，保存编辑递增版本，SQL 条件更新防止旧版本覆盖。
- 学生只能访问自己的简历，教师批量生成留给 P4。
- 简介最多120字，技能12项，教育/项目/实习各3项，奖项5项，经历每项最多3条且每条60字，正文全部字符串合计最多1200字。不为凑字数添加事实。

## 实施步骤与可观察验收条件

1. 环境与基线：安装 requirements，原有89项测试通过；不修改既有业务行为。
2. 结构与生成：FakeLLM 验证来源编号选择、排序、禁止编造、超长事实与重试；失败不保存记录。
3. 接口与编辑：列表、生成、分组表单、保存、重开；所有权及 CAS 版本检查通过，422仍保留原提交版本和输入。
4. 导出与预览：内存 DOCX、已保存版本打印、预览按屏宽缩放；未保存修改提示先保存。
5. 验证与文档：全量测试、Edge桌面/390px移动视口、Word与浏览器PDF排版检查；记录真实接口和客户端兼容性盲区。

## 接口

`GET /resumes`（可带 job_id）、`POST /resumes/generate`（job_id）、`GET/POST /resumes/{id}/edit`（保存提交 title/version/content_json）、`GET /resumes/{id}/print`、`GET /resumes/{id}/export.docx`。

页面使用原生 JS 组装结构化表单，无前端构建。服务接口为 `generate_resume(user, profile, job, llm)` 和 `export_resume_docx(content)`，供 P4 后续复用。
