## 执行策略

1. 严格按 P1 → P5 顺序执行；P2 与 P3 可以在 P1 通过后并行，但两人分别负责，避免同时改同一文件。
2. 每份计划在开始执行前才写完整代码级步骤，确保与上一阶段的真实代码一致。
3. 每个任务结束后运行该任务的测试并 Git 提交；每个阶段结束后运行全量测试并做一次手工冒烟。
4. 远程 push 前必须由用户确认；默认只做本地 commit。
5. 每天结束更新本路线图的状态列或勾选阶段验收项，避免“看起来在推进”。

## 阶段质量门

- P1 质量门：`pytest` 全绿；教师/学生/校友三种角色都能登录看到对应首页；岗位详情能看到技能和差距。
- P2 质量门：导出的 DOCX 在 Word/WPS 中打开正常；打印预览 ≤1.5 页；简历内容不含编造信息。
- P3 质量门：上传 60–90 秒视频能完成转写、评分、追问；失败可重试；报告可查看。
- P4 质量门：匹配分与技能数据一致；ZIP 内每位学生的简历文件名和岗位对应；CSV 含真实姓名与时间。
- P5 质量门：校园 Wi-Fi 与手机流量都能打开公网地址；10 位真人用户的最低使用标准全部达成；答辩彩排通过。

## 部署前技术检查（P5 必做）

- SQLite 使用 `create_all`，不会修改已部署表结构。首次部署后如需改表，必须使用 `ALTER TABLE` 运行手册（或引入 Alembic），并在改动前备份 `data/app.db`。
- 确认 `PRAGMA busy_timeout=5000`、`PRAGMA foreign_keys=ON`、`PRAGMA journal_mode=WAL` 生效。
